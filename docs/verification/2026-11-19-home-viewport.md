# 首页全屏布局修复验证

日期：2026-11-19

## 问题与修复

生产站 https://miguchn.com/ 的 `.hero` 被后加载样式固定为至少 700px，高度未与导航、底部提示共同计算。浏览器实测，1440×900 的下一章节从 y=845 开始，1440×720 仍从 y=845 开始，1920×1080 也从 y=845 开始；390×844 手机中文页下一章节从约 y=982 开始。

为首页正文与底部提示增加 `.home-screen`，以视口高度减导航高度作为最小高度，正文弹性占据剩余空间。插画按屏幕高度缩放；手机插画为独立控制按钮和状态反馈留出空间；较矮手机压缩标题及段间距。使用最小高度保留字体放大时自然撑高能力。

## 验证

- `npm run build`、`npm test`、`git diff --check` 全部通过。
- Brave 无头浏览器实测中英文：1440×900、1440×720、1920×1080、768×1024，下一章节顶部均等于视口高度，无横向溢出。
- 最终手机布局实测中英文：390×844、375×667，下一章节顶部均等于视口高度，无横向溢出。
- 已查看桌面 1440×900 与手机 390×844 截图，确认正文、插画、交互按钮和反馈可见。
- 轻量静态 review 覆盖导航目标、移动菜单、语言回切、动态 aria 标签、小岛交互、开场焦点恢复；未发现需追加修复的高置信异常。
- 生产首页 HTTP 200，生产 HTML/CSS 已读取；线上仍为修复前版本。本次未提交、推送或部署，修复后的生产验收须发布后执行。
